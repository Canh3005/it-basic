Hello Spring Boot — từ zero đến API đầu tiên

Spring Framework ra đời năm 2003 để thay thế J2EE nặng nề, nhưng cấu hình nó từng là cơn ác mộng XML. Spring Boot (2014) giữ nguyên toàn bộ sức mạnh của Spring và thêm ba thứ: starter (gom dependency), auto-configuration (tự cấu hình theo thứ có trên classpath) và embedded server (chạy bằng java -jar). Chương này đi từ ô tạo dự án trống đến một REST API chạy được — và quan trọng hơn, hiểu vì sao nó chạy với gần như không cấu hình.

Bài tập: 5 Quiz: 6 Prerequisites: Java cơ bản (sub-pillar Java, chương 1-9)
🎯 Mục tiêu chương
  • Phân biệt Spring Framework, Spring Boot và hệ sinh thái Spring.
  • Tạo dự án bằng Spring Initializr (web và curl), đọc hiểu cấu trúc thư mục và pom.xml.
  • Viết và chạy ứng dụng đầu tiên, gọi thử bằng curl.
  • Giải thích @SpringBootApplication thật sự gồm những gì.
  • Hiểu starter và dependency management (BOM) — vì sao không cần ghi version.
  • Hiểu cơ chế auto-configuration: điều kiện, thứ tự ưu tiên, cách tắt/ghi đè, cách debug.
  • Biết embedded server, fat JAR và đổi cổng, đổi server.
  • Dùng DevTools, logging và Actuator ở mức nhập môn.

1. Spring, Spring Boot — khác nhau thế nào?

Người mới hay gọi chung "Spring" cho mọi thứ, nhưng có ba lớp khác nhau:

LớpLà gìVí dụ
Spring FrameworkLõi: IoC container, AOP, MVC, transaction, data access@Autowired, @Transactional, RestTemplate
Spring BootLớp "có chính kiến" phủ lên Spring: starter, auto-config, embedded server, Actuator@SpringBootApplication, spring-boot-starter-web
Spring ProjectsThư viện riêng xây trên Spring/BootSpring Data, Spring Security, Spring Cloud, Spring Batch

Trước Boot, một ứng dụng web Spring cần: file web.xml, file applicationContext.xml khai báo từng bean, cấu hình DispatcherServlet, cấu hình view resolver, tự chọn version cho 20 thư viện sao cho tương thích nhau, rồi đóng gói WAR và triển khai vào Tomcat cài sẵn. Mất nửa ngày trước khi viết dòng code nghiệp vụ đầu tiên.

Spring Boot không thay thế Spring — nó cấu hình Spring giúp bạn. Mọi thứ bạn học ở các chương sau (DI, MVC, transaction…) vẫn là Spring Framework; Boot chỉ lo phần "lắp ráp".

Hai nguyên tắc thiết kế của Boot đáng nhớ ngay từ đầu:

  • Convention over configuration — có mặc định hợp lý cho mọi thứ; chỉ cấu hình khi muốn khác mặc định.
  • Back off khi bạn tự khai báo — nếu bạn tự tạo một bean, Boot rút lui và dùng bean của bạn. Mặc định luôn là "gợi ý", không bao giờ là "áp đặt".

4. @SpringBootApplication thực chất là gì?

Đây là meta-annotation — gộp ba annotation:

Khai triển
@SpringBootConfiguration     // = @Configuration: lớp này chứa định nghĩa bean
@EnableAutoConfiguration     // bật auto-configuration (mục 6)
@ComponentScan               // quét package hiện tại + con, tìm @Component/@Service/@Controller...
public @interface SpringBootApplication { }

Vì sao controller phải nằm dưới package của lớp main?

@ComponentScan không chỉ định basePackages nên mặc định quét từ package của lớp được chú thích trở xuống. Đặt HelloController ở vn.itbasic.other (ngang hàng, không phải con của vn.itbasic.demo) thì Spring không thấy — endpoint trả 404 mà không có thông báo lỗi nào. Đây là bẫy số một của người mới. Quy tắc: lớp main ở package gốc, mọi thứ khác ở bên dưới.

4.1. Chuyện gì xảy ra khi run() được gọi

1. Chuẩn bị
Đọc application.properties, biến môi trường, tham số dòng lệnh → Environment
2. Tạo context
Tạo ApplicationContext — container chứa mọi bean
3. Quét & đăng ký
@ComponentScan + auto-config tạo các BeanDefinition
4. Khởi tạo bean
Tạo bean, tiêm dependency (chương 2)
5. Mở server
Khởi động Tomcat nhúng, đăng ký DispatcherServlet
6. Sẵn sàng
Phát sự kiện ApplicationReadyEvent; log Started DemoApplication in 1.9 seconds
Toàn bộ vòng đời nằm trong một lời gọi SpringApplication.run().

6. Auto-configuration — phép màu có điều kiện

Khi @EnableAutoConfiguration bật, Boot đọc danh sách vài trăm lớp cấu hình trong file META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports (bên trong spring-boot-autoconfigure.jar). Mỗi lớp được bảo vệ bởi điều kiện; chỉ khi điều kiện thoả thì nó mới kích hoạt.

Minh hoạ cách một auto-config viết (rút gọn)
@AutoConfiguration
@ConditionalOnClass(DataSource.class)               // chỉ khi có JDBC trên classpath
public class DataSourceAutoConfiguration {

    @Bean
    @ConditionalOnMissingBean                       // chỉ khi BẠN CHƯA tự khai báo DataSource
    @ConditionalOnProperty("spring.datasource.url") // chỉ khi có cấu hình URL
    public DataSource dataSource(DataSourceProperties props) {
        return props.initializeDataSourceBuilder().build();
    }
}
Điều kiệnNghĩa
@ConditionalOnClassCó lớp X trên classpath (⇒ bạn đã thêm starter tương ứng)
@ConditionalOnMissingBeanChưa có bean kiểu X — cơ chế "back off" khi bạn tự khai báo
@ConditionalOnPropertyProperty trong application.properties có giá trị mong muốn
@ConditionalOnWebApplicationĐây là ứng dụng web (servlet/reactive)
Thêm starter ⇒ classpath thay đổi ⇒ điều kiện thoả ⇒ bean được tạo. Không có phép màu nào khác. Thêm spring-boot-starter-data-jpa và có spring.datasource.url, bạn tự động có DataSource, EntityManagerFactory, TransactionManager.

6.2. Ghi đè hoặc tắt

Hai cách
// Cách 1: tự khai báo bean cùng kiểu → auto-config "back off"
@Configuration
class MyConfig {
    @Bean
    ObjectMapper objectMapper() {                    // thay ObjectMapper mặc định của Boot
        return new ObjectMapper().findAndRegisterModules();
    }
}

// Cách 2: loại hẳn một auto-config
@SpringBootApplication(exclude = DataSourceAutoConfiguration.class)
public class DemoApplication { ... }
// hoặc: spring.autoconfigure.exclude=org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration
⚠️ Lỗi kinh điển ngày đầu

Thêm spring-boot-starter-data-jpa mà chưa cấu hình CSDL → ứng dụng không khởi động được: "Failed to configure a DataSource: 'url' attribute is not specified". Không phải bug: auto-config đã bật nhưng thiếu thông tin. Hoặc cấu hình spring.datasource.*, hoặc bỏ starter, hoặc exclude như trên.

spring-boot-starter-web kèm Tomcat nhúng như một thư viện bình thường — web server nằm trong ứng dụng chứ không phải ứng dụng nằm trong server. Hệ quả: một file duy nhất chạy ở mọi nơi.

8. DevTools, logging và Actuator

8.1. DevTools — vòng lặp phát triển nhanh

  • Tự restart khi file .class đổi (dùng hai classloader nên nhanh hơn khởi động lạnh nhiều).
  • LiveReload: trình duyệt tự tải lại khi file tĩnh đổi.
  • Tự bật cache template ở chế độ dev, tự tắt khi chạy bản đóng gói (java -jar).
  • IntelliJ: bật Build project automatically và Allow auto-make to start even if developer application is currently running để restart khi lưu.

8.2. Logging

Boot dùng SLF4J + Logback, đã cấu hình sẵn (cột màu, ngày giờ, tên thread). Đừng System.out.println — dùng logger:

LogDemo.java
@RestController
public class HelloController {

    private static final Logger log = LoggerFactory.getLogger(HelloController.class);

    @GetMapping("/hello")
    public String hello(@RequestParam(defaultValue = "Spring") String name) {
        log.info("Chào {}", name);          // {} thay vì nối chuỗi — chỉ ghép khi level bật
        log.debug("chi tiết chỉ thấy ở DEBUG");
        return "Xin chào, " + name + "!";
    }
}
application.properties
logging.level.root=INFO
logging.level.vn.itbasic=DEBUG                 # bật DEBUG riêng package của bạn
logging.level.org.springframework.web=DEBUG    # xem Spring MVC làm gì
logging.file.name=logs/app.log

Dự án đầu tiên, tạo bằng curl

Dùng lệnh curl ở mục 2 để tạo dự án với Java 21 và ba dependency web, actuator, devtools. Giải nén, chạy bằng ./mvnw spring-boot:run.

  • Gọi /actuator/health và chụp kết quả.
  • Đổi cổng sang 9000 bằng hai cách khác nhau (property và tham số dòng lệnh).
  • Mở log, tìm dòng Tomcat started on port và Started DemoApplication in.
Gợi ý

Cách 1: server.port=9000 trong application.properties. Cách 2: ./mvnw spring-boot:run -Dspring-boot.run.arguments=--server.port=9000. Tham số dòng lệnh luôn thắng file properties — thứ tự ưu tiên này là chủ đề chương 3.

Bẫy @ComponentScan

Tạo package vn.itbasic.other (ngang hàng với vn.itbasic.demo) và đặt một @RestController bên trong.

  • Quan sát: endpoint trả về gì? Có lỗi khi khởi động không?
  • Sửa bằng hai cách khác nhau.
Gợi ý

Cách 1: chuyển lớp main lên vn.itbasic (package cha chung). Cách 2: @SpringBootApplication(scanBasePackages = {"vn.itbasic"}) (hoặc @ComponentScan). Cách 1 là chuẩn; cách 2 chỉ dùng khi cấu trúc buộc phải thế.

Đọc báo cáo auto-configuration

Chạy với --debug và trả lời bằng cách tìm trong báo cáo:

  • Auto-config nào đã dựng DispatcherServlet?
  • Vì sao DataSourceAutoConfiguration nằm ở Negative matches?
  • Thêm spring-boot-starter-data-jpa (chưa cấu hình DB) và chạy lại — chuyện gì xảy ra? Giải thích bằng báo cáo.
Gợi ý

DispatcherServletAutoConfiguration. Negative vì thiếu lớp JDBC trên classpath (@ConditionalOnClass). Thêm JPA ⇒ lớp có mặt ⇒ điều kiện thoả ⇒ cần URL ⇒ lỗi Failed to configure a DataSource. Khắc phục: khai báo spring.datasource.url (H2 trong bộ nhớ đủ để thử).

Ghi đè bean mặc định

Boot tự tạo một ObjectMapper (Jackson). Làm cho API GET /now trả về LocalDate.now() dạng chuỗi 2025-03-01 thay vì mảng số [2025,3,1].

  • Viết endpoint trả LocalDate, xem JSON mặc định.
  • Cách 1: sửa bằng property. Cách 2: sửa bằng tự khai báo bean.
Gợi ý

Property: spring.jackson.serialization.write-dates-as-timestamps=false. Bean: khai báo @Bean Jackson2ObjectMapperBuilderCustomizer — hoặc thay hẳn ObjectMapper. Ưu tiên customizer/property vì không phá các mặc định khác của Boot.

Fat JAR và so sánh thời gian khởi động

Build fat JAR rồi chạy trên máy bạn. Sau đó bật spring.threads.virtual.enabled=true.

  • Dùng jar tf liệt kê nội dung: tìm BOOT-INF/lib/ và tomcat-embed-core-*.jar.
  • Ghi lại thời gian khởi động trước/sau khi bật virtual thread. Có khác không? Vì sao?
Gợi ý

Khởi động gần như không đổi: virtual thread ảnh hưởng cách xử lý request đồng thời, không phải thời gian boot. Lợi ích hiện ở tải cao với I/O chặn (chương 13).

Quiz

Q1

Spring Boot khác Spring Framework ở điểm nào?

Xem đáp án
✓ Đáp án

Spring Framework là lõi (IoC, MVC, transaction…). Spring Boot là lớp tự động lắp ráp phủ lên: starter (gom dependency), auto-configuration (tự cấu hình theo classpath), embedded server (chạy bằng java -jar), Actuator. Boot không thêm tính năng lõi mới — nó loại bỏ việc cấu hình thủ công.

Q2

@SpringBootApplication gồm những annotation nào?

Xem đáp án
✓ Đáp án

Ba cái: @SpringBootConfiguration (một @Configuration), @EnableAutoConfiguration (bật auto-config), @ComponentScan (quét bean từ package của lớp này trở xuống).

Hệ quả thực tế: lớp main phải ở package gốc. Controller đặt ở package ngang hàng sẽ không được quét.

Q3

Starter là gì? Vì sao khai báo starter không cần ghi version?

Xem đáp án
✓ Đáp án

Starter là dependency "gom" — một dòng kéo theo cả bộ thư viện tương thích. Version không cần ghi vì spring-boot-starter-parent (hoặc BOM spring-boot-dependencies) quản lý version cho hàng trăm thư viện, đã kiểm tra chạy cùng nhau.

Q4

Auto-configuration hoạt động ra sao và vì sao bạn "ghi đè" được nó?

Xem đáp án
✓ Đáp án

Boot đọc danh sách lớp auto-config; mỗi lớp có điều kiện (@ConditionalOnClass, @ConditionalOnProperty…). Bean mặc định gắn @ConditionalOnMissingBean nên khi bạn tự khai báo bean cùng kiểu, Boot tự rút lui — mặc định chỉ là gợi ý.

Q5

Làm sao biết một auto-config có được bật không, và vì sao?

Xem đáp án
✓ Đáp án

Chạy với --debug (hoặc debug=true) để in Conditions Evaluation Report: Positive matches (bật + lý do), Negative matches (không bật + điều kiện thiếu). Lúc ứng dụng chạy, dùng endpoint /actuator/conditions.

Q6

Embedded server có ý nghĩa gì với việc deploy?

Xem đáp án
✓ Đáp án

Server nằm trong ứng dụng ⇒ build ra một fat JAR chạy bằng java -jar ở bất cứ đâu có JRE; không cần cài/cấu hình Tomcat riêng. Phù hợp container (Docker) và CI/CD. WAR chỉ dùng khi buộc phải deploy vào server ứng dụng có sẵn.

Tổng kết

Sau chương 1, bạn đã nắm:

  • Spring là lõi, Spring Boot là lớp tự lắp ráp, Spring Projects là các thư viện riêng (Data, Security, Cloud…).
  • Initializr (web hoặc curl) tạo khung dự án; Maven Wrapper ./mvnw giữ phiên bản build nhất quán.
  • **@SpringBootApplication** = @Configuration + @EnableAutoConfiguration + @ComponentScan — lớp main đặt ở package gốc.
  • Starter gom dependency; parent/BOM quản lý version.
  • Auto-configuration là cấu hình có điều kiện; @ConditionalOnMissingBean cho phép bạn ghi đè; debug bằng --debug.
  • Embedded Tomcat + fat JAR ⇒ deploy một file; Java 21 bật virtual threads bằng một property.
  • DevTools (restart nhanh), Logback/SLF4J (logging), Actuator (health, metrics) — mở có chọn lọc.

Chương 04 · Spring MVC & REST

Spring MVC & REST API — từ request đến JSON

REST API là thứ bạn sẽ viết nhiều nhất với Spring Boot. Chương này trả lời hai câu: một request đi qua những gì từ lúc vào Tomcat đến lúc ra JSON, và thiết kế một API CRUD đúng chuẩn (đúng động từ, đúng mã trạng thái, đúng header). Dữ liệu tạm giữ trong bộ nhớ — CSDL thật vào ở chương 6.

Bài tập: 5 Quiz: 6 Prerequisites: Chương 1-3
🎯 Mục tiêu chương
  • Vẽ được luồng xử lý request qua DispatcherServlet, HandlerMapping, HttpMessageConverter.
  • Viết controller với @RestController và các @GetMapping/@PostMapping/@PutMapping/@PatchMapping/@DeleteMapping.
  • Nhận dữ liệu: @PathVariable, @RequestParam, @RequestBody, @RequestHeader.
  • Trả dữ liệu đúng chuẩn: ResponseEntity, mã trạng thái, header Location.
  • Tuỳ biến JSON bằng Jackson: tên trường, ẩn trường, định dạng ngày.
  • Phân biệt Filter, Interceptor, **@ControllerAdvice** — mỗi cái nằm ở đâu.
  • Xử lý upload/download file và content negotiation ở mức cơ bản.

1. Một request đi qua những gì?

Khi GET /api/products/42 đến, trước khi code controller của bạn chạy đã có cả một dây chuyền:

1. Tomcat
Nhận kết nối TCP, phân tích HTTP thành HttpServletRequest
2. Filter chain
Servlet Filter (Security, CORS, logging…)
3. DispatcherServlet
Front controller — cửa vào duy nhất của Spring MVC
4. HandlerMapping
Tìm controller + method khớp URL & HTTP method
5. Interceptor (trước)
preHandle của HandlerInterceptor
6. Giải tham số
@PathVariable, @RequestBody (JSON → object nhờ Jackson)
7. Method của bạn
Chạy logic, trả về object / ResponseEntity
8. HttpMessageConverter
Object → JSON (Jackson), ghi vào response
Lỗi xảy ra ở bất cứ bước nào đều được @ControllerAdvice (chương 5) bắt và chuyển thành response.
**DispatcherServlet là pattern Front Controller**: mọi request đi qua một cửa, rồi được phân phát. Bạn không bao giờ tự đăng ký servlet cho từng endpoint — Boot đã cấu hình sẵn (chương 1).

2. Controller đầu tiên

ProductController.java
@RestController                          // = @Controller + @ResponseBody: mọi method trả về BODY (JSON)
@RequestMapping("/api/products")         // tiền tố chung cho cả lớp
public class ProductController {

    private final ProductService service;

    public ProductController(ProductService service) {
        this.service = service;
    }

    @GetMapping                          // GET /api/products
    public List<Product> list() {
        return service.findAll();
    }

    @GetMapping("/{id}")                 // GET /api/products/42
    public Product get(@PathVariable long id) {
        return service.findById(id);
    }
}
AnnotationHTTPDùng choIdempotent?
@GetMappingGETĐọc tài nguyên✅ (và an toàn)
@PostMappingPOSTTạo mới / hành động❌
@PutMappingPUTThay thế toàn bộ tài nguyên✅
@PatchMappingPATCHCập nhật một phầnTuỳ thiết kế
@DeleteMappingDELETEXoá✅

@Controller hay @RestController?

@Controller trả về tên view (Thymeleaf/JSP — web server-side rendering). @RestController trả về dữ liệu ghi thẳng vào body, dùng cho API. Với kiến trúc SPA (React/Vue) + API, bạn gần như chỉ dùng @RestController.

💡 Dùng DTO, đừng nhận thẳng entity

@RequestBody nhận DTO (record) riêng cho từng use case (CreateProductRequest, UpdateProductRequest), không nhận entity của CSDL. Nếu không, client có thể ghi đè trường như id, createdAt, role (mass assignment). Chương 8 trình bày kiến trúc DTO đầy đủ.

Ghi chú tên tham số: Spring dùng tên biến Java làm tên tham số nếu bạn không ghi rõ (cần biên dịch với -parameters, Boot/Maven plugin đã bật sẵn). Ghi rõ @PathVariable("id") là cách an toàn khi tên API ≠ tên biến.

Tạo mới + Location
@PostMapping
public ResponseEntity<Product> create(@RequestBody CreateProductRequest req) {
    Product saved = service.create(req);

    URI location = ServletUriComponentsBuilder.fromCurrentRequest()   // http://host/api/products
            .path("/{id}").buildAndExpand(saved.id()).toUri();        // + /43

    return ResponseEntity.created(location).body(saved);              // 201 + Location + body
}

@DeleteMapping("/{id}")
@ResponseStatus(HttpStatus.NO_CONTENT)                                // 204 — không cần ResponseEntity
public void delete(@PathVariable long id) {
    service.delete(id);
}

@GetMapping("/{id}")
public ResponseEntity<Product> get(@PathVariable long id) {
    return service.findById(id)                                       // Optional<Product>
            .map(ResponseEntity::ok)                                  // 200
            .orElseGet(() -> ResponseEntity.notFound().build());      // 404
}

4.1. PUT khác PATCH

PUTPATCH
Ngữ nghĩaThay thế toàn bộ tài nguyênSửa một phần
BodyPhải đủ mọi trườngChỉ trường cần đổi

⚠️ Bẫy với PATCH

Với record UpdateRequest(String name, Long price), "client không gửi price" và "client gửi price: null" **cùng cho null* — không phân biệt được ý định *giữ nguyên hay xoá. Hầu hết API chấp nhận quy ước "null = không đổi"; nếu cần phân biệt thật, dùng JSON Merge Patch (Map<String, Object>) hoặc JsonNullable.

5. Jackson — chuyển đổi JSON ↔ object

spring-boot-starter-web kèm Jackson; Boot tự cấu hình ObjectMapper với module jackson-datatype-jsr310 (hỗ trợ java.time). Vài tuỳ biến thường gặp:

ProductDto.java
public record ProductDto(
        long id,
        String name,

        @JsonProperty("unit_price")                         // tên trường trong JSON khác tên trong Java
        long price,

        @JsonIgnore                                         // không bao giờ ra JSON
        String internalCode,

        @JsonFormat(pattern = "dd/MM/yyyy")                 // chỉ định định dạng ngày cho field này
        LocalDate releaseDate,

        @JsonInclude(JsonInclude.Include.NON_NULL)          // bỏ khỏi JSON nếu null
        String description) { }
application.yml
spring:
  jackson:
    property-naming-strategy: SNAKE_CASE         # toàn bộ API dùng snake_case: unit_price, release_date...
    default-property-inclusion: non_null         # bỏ mọi trường null
    serialization:
      write-dates-as-timestamps: false           # LocalDate → "2025-03-01" thay vì [2025,3,1]
    deserialization:
      fail-on-unknown-properties: false          # client gửi thừa trường → bỏ qua (mặc định của Boot)
💡 Quyết định naming một lần

Chọn camelCase hay snake_case cho toàn API và cấu hình ở một chỗ (property-naming-strategy). API vừa unitPrice vừa unit_price là mùi thiết kế tệ. Frontend JS thường thích camelCase; hệ thống đa ngôn ngữ/Python thường dùng snake_case — chọn theo người tiêu thụ chính.

6. Một API CRUD hoàn chỉnh (lưu trong bộ nhớ)

ProductService.java
@Service
public class ProductService {

    private final Map<Long, Product> store = new ConcurrentHashMap<>();   // thread-safe (singleton!)
    private final AtomicLong seq = new AtomicLong();

    public List<Product> findAll() { return List.copyOf(store.values()); }

    public Optional<Product> findById(long id) { return Optional.ofNullable(store.get(id)); }

    public Product create(CreateProductRequest r) {
        long id = seq.incrementAndGet();
        Product p = new Product(id, r.name(), r.price());
        store.put(id, p);
        return p;
    }

    public Optional<Product> replace(long id, CreateProductRequest r) {
        if (!store.containsKey(id)) return Optional.empty();
        Product p = new Product(id, r.name(), r.price());
        store.put(id, p);
        return Optional.of(p);
    }

    public boolean delete(long id) { return store.remove(id) != null; }
}

public record Product(long id, String name, long price) { }
ProductController.java
@RestController
@RequestMapping("/api/products")
public class ProductController {

    private final ProductService service;
    public ProductController(ProductService service) { this.service = service; }

    @GetMapping
    public List<Product> list() { return service.findAll(); }

    @GetMapping("/{id}")
    public Product get(@PathVariable long id) {
        return service.findById(id).orElseThrow(
                () -> new ResponseStatusException(HttpStatus.NOT_FOUND, "Không có sản phẩm " + id));
    }

    @PostMapping
    public ResponseEntity<Product> create(@RequestBody CreateProductRequest req) {
        Product p = service.create(req);
        URI uri = ServletUriComponentsBuilder.fromCurrentRequest().path("/{id}").buildAndExpand(p.id()).toUri();
        return ResponseEntity.created(uri).body(p);
    }

    @PutMapping("/{id}")
    public Product replace(@PathVariable long id, @RequestBody CreateProductRequest req) {
        return service.replace(id, req).orElseThrow(
                () -> new ResponseStatusException(HttpStatus.NOT_FOUND));
    }

    @DeleteMapping("/{id}")
    @ResponseStatus(HttpStatus.NO_CONTENT)
    public void delete(@PathVariable long id) {
        if (!service.delete(id)) throw new ResponseStatusException(HttpStatus.NOT_FOUND);
    }
}

7. Content negotiation, upload & download

7.1. Content negotiation

Client nói nó muốn gì bằng header Accept và gửi gì bằng Content-Type; Spring chọn HttpMessageConverter tương ứng. Có thể ràng buộc:

produces / consumes
@PostMapping(consumes = MediaType.APPLICATION_JSON_VALUE,
             produces = MediaType.APPLICATION_JSON_VALUE)
public Product create(@RequestBody CreateProductRequest req) { ... }
// Content-Type khác JSON  → 415 Unsupported Media Type
// Accept không chứa JSON  → 406 Not Acceptable

7.2. Upload file

FileController.java
@PostMapping(path = "/api/files", consumes = MediaType.MULTIPART_FORM_DATA_VALUE)
public Map<String, Object> upload(@RequestParam("file") MultipartFile file) throws IOException {
    if (file.isEmpty()) throw new ResponseStatusException(HttpStatus.BAD_REQUEST, "File rỗng");
    if (!"image/png".equals(file.getContentType()))
        throw new ResponseStatusException(HttpStatus.UNSUPPORTED_MEDIA_TYPE, "Chỉ nhận PNG");

    Path dir = Path.of("uploads");
    Files.createDirectories(dir);
    // KHÔNG dùng file.getOriginalFilename() làm tên file: có thể là "../../etc/passwd"
    Path dest = dir.resolve(UUID.randomUUID() + ".png");
    file.transferTo(dest);
    return Map.of("name", dest.getFileName().toString(), "size", file.getSize());
}
application.yml
spring:
  servlet:
    multipart:
      max-file-size: 5MB
      max-request-size: 10MB            # vượt → 413 Payload Too Large
🔒 Quy tắc an toàn khi nhận file

(1) Giới hạn kích thước; (2) kiểm tra loại bằng nội dung chứ không chỉ Content-Type (client nói dối được); (3) tự sinh tên file, không tin tên người dùng gửi (path traversal); (4) lưu ngoài thư mục được phục vụ tĩnh; (5) production nên đẩy lên object storage (S3/GCS) thay vì ổ đĩa của server.

7.3. Download

Tải file
@GetMapping("/api/files/{name}")
public ResponseEntity<Resource> download(@PathVariable String name) {
    Resource file = new FileSystemResource(Path.of("uploads").resolve(name).normalize());
    if (!file.exists()) return ResponseEntity.notFound().build();
    return ResponseEntity.ok()
            .contentType(MediaType.IMAGE_PNG)
            .header(HttpHeaders.CONTENT_DISPOSITION, "attachment; filename=\"" + name + "\"")
            .body(file);
}

RequestIdFilter.java
@Component
class RequestIdFilter extends OncePerRequestFilter {          // chạy đúng 1 lần/request

    @Override
    protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res, FilterChain chain)
            throws ServletException, IOException {
        String id = Optional.ofNullable(req.getHeader("X-Request-Id")).orElse(UUID.randomUUID().toString());
        MDC.put("requestId", id);                              // log pattern %X{requestId} sẽ in ra
        res.setHeader("X-Request-Id", id);
        try {
            chain.doFilter(req, res);                          // chuyển tiếp xuống dưới
        } finally {
            MDC.clear();                                       // luôn dọn — thread được tái sử dụng
        }
    }
}
TimingInterceptor.java
@Component
class TimingInterceptor implements HandlerInterceptor {

    @Override public boolean preHandle(HttpServletRequest req, HttpServletResponse res, Object handler) {
        req.setAttribute("t0", System.nanoTime());
        return true;                                           // false = chặn request
    }

    @Override public void afterCompletion(HttpServletRequest req, HttpServletResponse res, Object handler, Exception ex) {
        long ms = (System.nanoTime() - (long) req.getAttribute("t0")) / 1_000_000;
        LoggerFactory.getLogger("timing").info("{} {} -> {} ({} ms)", req.getMethod(), req.getRequestURI(), res.getStatus(), ms);
    }
}

@Configuration
class WebConfig implements WebMvcConfigurer {
    private final TimingInterceptor timing;
    WebConfig(TimingInterceptor timing) { this.timing = timing; }

    @Override public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(timing).addPathPatterns("/api/**");
    }
}

9. CORS — frontend ở origin khác

Trình duyệt chặn trang http://localhost:3000 (React) gọi API ở http://localhost:8080 trừ khi API cho phép bằng header CORS. Cấu hình tập trung (khi dùng Spring Security, đặt trong security config — chương 9):

WebConfig.java
@Override
public void addCorsMappings(CorsRegistry registry) {
    registry.addMapping("/api/**")
            .allowedOrigins("http://localhost:3000", "https://shop.example.com")   // KHÔNG dùng "*" khi có cookie/credential
            .allowedMethods("GET", "POST", "PUT", "PATCH", "DELETE")
            .allowedHeaders("*")
            .maxAge(3600);
}

Bài tập

CRUD sách

Xây API /api/books (id, title, author, year) lưu trong ConcurrentHashMap. Đủ GET danh sách, GET theo id, POST, PUT, DELETE.

  • Đúng mã: 201+Location, 204, 404.
  • Thêm lọc GET /api/books?author=Nam&year=2020 bằng @RequestParam tuỳ chọn.
  • Viết .http file hoặc script curl thử cả 5 thao tác.
Gợi ý

Lọc: dùng stream().filter(...) với điều kiện author == null || b.author().equalsIgnoreCase(author). Nhớ rằng store là ConcurrentHashMap vì service là singleton.

Bảng mã trạng thái

Với API sách ở trên, ghi ra giấy mã trạng thái đúng cho từng tình huống, rồi kiểm chứng bằng curl -i:

  • Tạo sách thành công; tạo sách trùng ISBN.
  • Xoá sách không tồn tại; xoá hai lần liên tiếp (idempotent?).
  • Gọi POST với Content-Type: text/plain.
  • Gọi GET /api/books/abc (id không phải số).
Gợi ý

201; 409. 404 (hoặc 204 nếu coi xoá idempotent — hãy chọn một quy ước và ghi vào tài liệu API). 415. Với abc: MethodArgumentTypeMismatchException ⇒ Boot trả 400 — chương 5 sẽ chuẩn hoá nội dung lỗi.

Tuỳ biến JSON

Cho record Book(long id, String title, String authorName, LocalDate publishedAt, String internalNote).

  • JSON ra: book_title, author_name; ngày dạng dd/MM/yyyy; không chứa internalNote.
  • Làm 2 lần: (a) bằng annotation trên record, (b) toàn cục bằng spring.jackson.*. Khi nào chọn cách nào?
Gợi ý

(a) @JsonProperty, @JsonFormat, @JsonIgnore — đặc thù từng DTO. (b) property-naming-strategy: SNAKE_CASE — nhất quán toàn API. Thường kết hợp: (b) cho quy ước chung, (a) cho ngoại lệ.

Request ID & thời gian xử lý

Viết OncePerRequestFilter gắn X-Request-Id (nhận từ client hoặc tự sinh) vào response và vào log (MDC), và HandlerInterceptor log METHOD URI -> status (ms).

  • Sửa logging.pattern.level để in %X{requestId}.
  • Gọi 3 request — các dòng log cùng request phải có cùng requestId.
  • Vì sao phải MDC.clear() trong finally?
Gợi ý

logging.pattern.level: "%5p [%X{requestId}]". Container tái sử dụng thread trong pool ⇒ không clear thì requestId cũ rò sang request khác (log sai, nguy hiểm khi điều tra sự cố).

Upload ảnh an toàn

Viết POST /api/avatars nhận ảnh PNG/JPEG ≤ 2 MB, lưu vào uploads/, trả về URL tải.

  • Tên file do server sinh.
  • Từ chối file không phải ảnh bằng cách đọc magic bytes (89 50 4E 47 cho PNG; FF D8 FF cho JPEG), không chỉ tin Content-Type.
  • Viết endpoint GET /api/avatars/{name} và thử ..%2F..%2Fpom.xml — chuyện gì xảy ra? Chặn thế nào?
Gợi ý

Chặn path traversal: Path p = dir.resolve(name).normalize(); if (!p.startsWith(dir)) throw 400/404. Tốt hơn: chỉ chấp nhận tên khớp regex [0-9a-f-]{36}\\.(png|jpg).

Quiz

Q1

Mô tả đường đi của một request trong Spring MVC.

Xem đáp án
✓ Đáp án

Tomcat → các Filter → **DispatcherServlet** → HandlerMapping (tìm method) → interceptor preHandle → giải tham số (HttpMessageConverter đọc JSON) → method controller → HttpMessageConverter ghi JSON → interceptor postHandle/afterCompletion → response. Exception ở giữa → @ControllerAdvice.

Q2

PUT khác PATCH thế nào? Khi nào dùng cái nào?

Xem đáp án
✓ Đáp án

PUT thay thế toàn bộ tài nguyên (body phải đủ trường, idempotent); PATCH sửa một phần. Dùng PUT khi client có sẵn toàn bộ đối tượng (form chỉnh sửa đầy đủ); PATCH khi chỉ đổi vài trường (đổi trạng thái, đổi tên).

Q3

Tạo mới nên trả mã nào và kèm gì?

Xem đáp án
✓ Đáp án

201 Created, kèm header **Location** trỏ tới tài nguyên mới, và (thường) body là tài nguyên vừa tạo. Không trả 200 rồi để client tự đoán id.

Q4

401 khác 403 thế nào?

Xem đáp án
✓ Đáp án

401: chưa xác thực (không có/hết hạn token) — "bạn là ai?". 403: đã xác thực nhưng không đủ quyền — "tôi biết bạn, nhưng bạn không được làm vậy". Nhầm hai mã này là lỗi API rất phổ biến.

Q5

Vì sao không nhận thẳng entity trong @RequestBody?

Xem đáp án
✓ Đáp án

Client có thể gửi cả các trường nó không được phép đặt (id, role, createdAt…) — mass assignment. DTO riêng cho từng use case xác định đúng tập trường chấp nhận, tách biệt hợp đồng API khỏi mô hình CSDL (đổi bảng không vỡ API).

Q6

Filter và Interceptor khác nhau ở đâu?

Xem đáp án
✓ Đáp án

Filter thuộc Servlet container, chạy trước DispatcherServlet, không biết controller nào xử lý — hợp cho security, CORS, log toàn bộ. Interceptor thuộc Spring MVC, chạy quanh controller và biết handler — hợp cho đo thời gian, kiểm tra theo endpoint.

Tổng kết

Sau chương 4, bạn đã nắm:

  • Luồng: **Tomcat → Filter → DispatcherServlet → HandlerMapping → controller → HttpMessageConverter**.
  • **@RestController** + @GetMapping/@PostMapping/@PutMapping/@PatchMapping/@DeleteMapping.
  • Nhận dữ liệu bằng **@PathVariable, @RequestParam, @RequestBody (DTO/record), @RequestHeader**.
  • Trả đúng mã: 201+Location, 204, 404, 409; ResponseEntity khi cần kiểm soát header/status.
  • Jackson: @JsonProperty/@JsonIgnore/@JsonFormat hoặc cấu hình spring.jackson.* toàn cục.
  • **Filter / Interceptor / @ControllerAdvice ở ba tầng khác nhau; upload file** cần giới hạn kích thước, tự sinh tên, kiểm tra nội dung.

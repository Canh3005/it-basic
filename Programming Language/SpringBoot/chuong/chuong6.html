Chương 06 · Spring Data JPA

Spring Data JPA — nói chuyện với CSDL không cần viết JDBC

Ở sub-pillar Java (chương 13) bạn đã viết JDBC bằng tay: mở kết nối, PreparedStatement, duyệt ResultSet, ánh xạ từng cột. Làm vài lần thì ổn, làm cho 50 bảng thì kiệt sức. JPA cho phép bạn làm việc với đối tượng Java và để thư viện sinh SQL; Spring Data JPA đi thêm một bước: bạn chỉ khai báo interface, nó tự sinh cài đặt. Chương này dựng lớp truy cập dữ liệu cho API ở chương 4-5.

2.1. HikariCP — connection pool

Mở một kết nối CSDL đắt (TCP + xác thực, vài chục ms). Boot dùng HikariCP giữ sẵn một nhóm kết nối và cho mượn/trả. Hai ý quan trọng:

  • Pool nhỏ thường tốt hơn. maximum-pool-size mặc định 10 là hợp lý cho đa số ứng dụng; CSDL xử lý song song được ít hơn bạn nghĩ. Công thức gợi ý của HikariCP: (số lõi CPU của DB × 2) + số ổ đĩa.
  • Pool cạn = ứng dụng treo. Nếu mọi kết nối đang bị giữ (transaction dài, gọi API ngoài trong transaction), request mới chờ connection-timeout rồi lỗi "Connection is not available". Giữ transaction ngắn.

3. Entity — ánh xạ bảng thành lớp

Product.java
@Entity
@Table(name = "products")
@EntityListeners(AuditingEntityListener.class)
public class Product {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)       // PostgreSQL: cột BIGSERIAL/IDENTITY
    private Long id;

    @Column(nullable = false, length = 200)
    private String name;

    @Column(nullable = false, precision = 12, scale = 2)       // NUMERIC(12,2)
    private BigDecimal price;                                  // tiền: BigDecimal, không dùng double

    @Column(nullable = false, length = 50)
    private String category;

    @Enumerated(EnumType.STRING)                               // lưu "ACTIVE", không lưu số thứ tự
    @Column(nullable = false, length = 20)
    private ProductStatus status = ProductStatus.ACTIVE;

    @CreatedDate
    @Column(nullable = false, updatable = false)
    private Instant createdAt;

    @LastModifiedDate
    private Instant updatedAt;

    protected Product() { }                                    // JPA bắt buộc có constructor không tham số

    public Product(String name, BigDecimal price, String category) {
        this.name = name;
        this.price = price;
        this.category = category;
    }

    // Hành vi nghiệp vụ thay vì setter tràn lan
    public void changePrice(BigDecimal newPrice) {
        if (newPrice.signum() <= 0) throw new IllegalArgumentException("Giá phải > 0");
        this.price = newPrice;
    }
    public void discontinue() { this.status = ProductStatus.DISCONTINUED; }

    public Long getId() { return id; }
    public String getName() { return name; }
    public BigDecimal getPrice() { return price; }
    public String getCategory() { return category; }
    public ProductStatus getStatus() { return status; }
    public Instant getCreatedAt() { return createdAt; }
}

public enum ProductStatus { ACTIVE, DISCONTINUED }

@Configuration
@EnableJpaAuditing                                             // bật @CreatedDate/@LastModifiedDate
class JpaConfig { }

⚠️ Tên method dài là mùi code

5. @Query — khi cần toàn quyền

ProductRepository.java
// JPQL — truy vấn trên ENTITY & thuộc tính, không phải bảng & cột
@Query("select p from Product p where p.category = :category and p.price <= :max order by p.price")
List<Product> cheapInCategory(@Param("category") String category, @Param("max") BigDecimal max);

// Thống kê: trả về nhiều cột → dùng projection (mục 5.1)
@Query("select p.category as category, count(p) as total, avg(p.price) as avgPrice " +
       "from Product p where p.status = 'ACTIVE' group by p.category")
List<CategoryStats> statsByCategory();

// Câu UPDATE/DELETE hàng loạt: phải có @Modifying
@Modifying(clearAutomatically = true)                    // xoá persistence context sau khi chạy (chương 7)
@Query("update Product p set p.status = 'DISCONTINUED' where p.category = :category")
int discontinueCategory(@Param("category") String category);

// SQL thuần khi JPQL không đủ (hàm đặc thù PostgreSQL, full-text…)
@Query(value = "select * from products where to_tsvector('simple', name) @@ plainto_tsquery('simple', :q)",
       nativeQuery = true)
List<Product> fullTextSearch(@Param("q") String q);
**Luôn dùng tham số có tên (:max + @Param), không bao giờ nối chuỗi vào câu query. Tham số được driver bind nên miễn nhiễm SQL injection**. Nối chuỗi "... where name = '" + name + "'" là mở cửa cho nó (xem Java chương 13).

5.1. Projection — chỉ lấy cột cần

Tải cả entity (mọi cột, kèm quan hệ) chỉ để hiện hai trường là phí. Projection trả về một "mặt cắt":

Projection
// (a) Interface projection — getter khớp tên cột/alias
public interface CategoryStats {
    String getCategory();
    long getTotal();
    BigDecimal getAvgPrice();
}

// (b) DTO record — dùng với "select new" (an toàn kiểu, gọn)
public record ProductSummary(Long id, String name, BigDecimal price) { }

@Query("select new vn.itbasic.shop.ProductSummary(p.id, p.name, p.price) from Product p where p.category = :c")
List<ProductSummary> summaries(@Param("c") String category);

// (c) Derived query cũng nhận projection
List<ProductSummary> findByStatus(ProductStatus status);       // chỉ SELECT các cột cần

6. Phân trang & sắp xếp

Không bao giờ trả về toàn bộ bảng. Pageable mô tả "trang số mấy, mỗi trang bao nhiêu, sắp xếp thế nào":

Repository & service
Page<Product> findByCategory(String category, Pageable pageable);     // thêm tham số Pageable

// Gọi:
Pageable pageable = PageRequest.of(0, 20, Sort.by("price").descending().and(Sort.by("name")));
Page<Product> page = repo.findByCategory("sach", pageable);

page.getContent();         // List<Product> của trang này
page.getTotalElements();   // tổng số bản ghi — tốn thêm 1 câu COUNT(*)
page.getTotalPages();
page.getNumber();          // trang hiện tại (đếm từ 0)
page.hasNext();
Controller — Spring tự đọc ?page=&size=&sort=
@GetMapping("/api/products")
PagedResponse<ProductSummary> list(
        @RequestParam String category,
        @PageableDefault(size = 20, sort = "createdAt", direction = Sort.Direction.DESC) Pageable pageable) {

    Page<ProductSummary> page = service.search(category, pageable);
    return PagedResponse.from(page);                          // trả DTO riêng, không trả thẳng PageImpl
}

public record PagedResponse<T>(List<T> items, int page, int size, long totalItems, int totalPages) {
    static <T> PagedResponse<T> from(Page<T> p) {
        return new PagedResponse<>(p.getContent(), p.getNumber(), p.getSize(), p.getTotalElements(), p.getTotalPages());
    }
}
// GET /api/products?category=sach&page=1&size=10&sort=price,desc
KiểuCó COUNT(*)?Biết tổng số?Dùng khi
Page<T>✅ (1 câu thêm)✅Giao diện có số trang (1,2,3…)
Slice<T>❌ (lấy size+1 bản ghi)❌, chỉ biết hasNext()"Tải thêm" / cuộn vô hạn — rẻ hơn
List<T> + Pageable❌❌Chỉ cần dữ liệu, không cần metadata
⚠️ Offset lớn thì chậm

OFFSET 1000000 LIMIT 20 buộc CSDL đọc rồi bỏ 1.000.000 dòng. Với dữ liệu rất lớn dùng keyset pagination (seek method): where id < :lastId order by id desc limit 20 — Spring Data hỗ trợ qua ScrollPosition (3.1+). Trả về PageImpl thẳng ra JSON cũng bị Spring Data cảnh báo vì cấu trúc không ổn định — dùng DTO như trên hoặc PagedModel.

💡 Chặn size lớn

Client gửi ?size=1000000 là đủ làm sập server. Spring giới hạn size tối đa 2000 mặc định (spring.data.web.pageable.max-page-size); hãy đặt thấp hơn, ví dụ 100.

Bài tập

Dựng tầng dữ liệu cho Book

Chạy PostgreSQL (Docker). Tạo entity Book(id, title, author, isbn UNIQUE, price, publishedYear, status); BookRepository; endpoint POST/GET /api/books thay thế ConcurrentHashMap ở chương 4.

  • ddl-auto: create để học; bật log SQL.
  • Tạo 3 sách, đọc log: bạn thấy câu INSERT nào?
  • Khởi động lại — dữ liệu còn không? Đổi sang validate thì sao?
Gợi ý

create xoá & tạo lại bảng mỗi lần khởi động nên dữ liệu mất; validate giữ dữ liệu nhưng bảng phải tồn tại và khớp entity — chính vì vậy cần migration (chương 7).

Derived query vs @Query

Viết ba truy vấn cho Book:

  • findByAuthorIgnoreCase; findByPublishedYearBetween; existsByIsbn.
  • @Query trả 5 tác giả có nhiều sách nhất (select b.author, count(b) …) dùng projection interface.
  • Chuyển một derived query dài thành @Query và nêu lý do.
Gợi ý

Group by + order by count(b) desc rồi lấy 5 dòng đầu bằng Pageable.ofSize(5) hoặc limit (Hibernate 6 hỗ trợ limit trong JPQL). Projection cần alias khớp tên getter: as author, as total.

Phân trang đúng cách

Tạo 1.000 sách bằng ApplicationRunner. Viết GET /api/books?page=&size=&sort= trả PagedResponse<BookSummary>.

  • Thử size=100000 — chuyện gì xảy ra? Chặn bằng max-page-size.
  • Thử sort=khongTonTai,asc — lỗi gì? (PropertyReferenceException).
  • So sánh số câu SQL của Page và Slice trong log.
Gợi ý

Page phát 2 câu (select + count), Slice chỉ 1 câu (lấy size+1). Lỗi sort không hợp lệ nên được @ExceptionHandler biến thành 400 (chương 5) — đó là dữ liệu client gửi sai, không phải 500.

Săn lỗi entity

Chỉ ra ít nhất 5 vấn đề và sửa:

Order.java
@Entity
public record Order(
        @Id Long id,
        double total,
        @Enumerated String status,
        LocalDateTime createdAt) { }
Gợi ý

(1) record không làm entity được (final, không constructor rỗng, bất biến); (2) double cho tiền → BigDecimal; (3) @Enumerated mặc định ORDINAL và kiểu String vô nghĩa — dùng enum + EnumType.STRING; (4) LocalDateTime mơ hồ múi giờ → Instant; (5) @Id thiếu @GeneratedValue; (6) thiếu @Table/@Column(nullable=false).

Đo pool kết nối

Đặt maximum-pool-size: 2, connection-timeout: 1000. Viết endpoint GET /slow có @Transactional rồi Thread.sleep(5000) bên trong.

  • Gọi /slow 3 lần song song bằng curl &: request thứ 3 nhận lỗi gì, sau bao lâu?
  • Xem /actuator/metrics/hikaricp.connections.active và hikaricp.connections.pending.
  • Nêu 2 cách tránh trên thực tế.
Gợi ý

Lỗi Connection is not available, request timed out after 1000ms. Cách tránh: không giữ transaction/kết nối trong lúc chờ I/O chậm (gọi API ngoài, sleep), hoặc tách phần I/O ra ngoài transaction; không phải cứ tăng pool là xong.

Quiz

Q1

JPA, Hibernate và Spring Data JPA khác nhau thế nào?

Xem đáp án
✓ Đáp án

JPA là đặc tả (jakarta.persistence); Hibernate là cài đặt phổ biến nhất của JPA (sinh SQL, cache, dirty checking); Spring Data JPA là lớp của Spring bên trên — tự sinh cài đặt repository từ interface, thêm phân trang và @Query.

Q2

Vì sao nên dùng @Enumerated(EnumType.STRING)?

Xem đáp án
✓ Đáp án

Mặc định ORDINAL lưu số thứ tự (0,1,2). Chèn/đổi thứ tự enum sẽ làm dữ liệu cũ hiểu sai âm thầm. STRING lưu tên ("ACTIVE") — bền vững, dễ đọc khi truy vấn trực tiếp.

Q3

Derived query hoạt động ra sao? Giới hạn của nó?

Xem đáp án
✓ Đáp án

Spring Data phân tích tên method (findByCategoryAndStatus) thành truy vấn lúc khởi động; sai tên thuộc tính ⇒ ứng dụng không khởi động. Giới hạn: tên dài, khó đọc khi > ~3 điều kiện, không lọc động — khi đó dùng @Query hoặc Specification.

Q4

Vì sao không nối chuỗi vào câu @Query?

Xem đáp án
✓ Đáp án

Mở cửa cho SQL injection. Tham số có tên (:name + @Param) được bind qua PreparedStatement nên dữ liệu người dùng không bao giờ được hiểu là mã SQL.

Q5

Page và Slice khác nhau? Khi nào chọn cái nào?

Xem đáp án
✓ Đáp án

Page thực hiện thêm COUNT(*) để biết tổng số bản ghi/trang — hợp giao diện đánh số trang. Slice chỉ lấy size+1 bản ghi để biết còn trang sau — rẻ hơn, hợp "tải thêm"/cuộn vô hạn. Với dữ liệu khổng lồ, dùng keyset pagination vì OFFSET lớn rất chậm.

Q6

Vì sao không nên dùng ddl-auto: update ở production?

Xem đáp án
✓ Đáp án

Hành vi không dự đoán được (không xoá/đổi cột, có thể sinh schema khác ý), không có lịch sử, không rollback, không review. Schema nên quản lý bằng migration có phiên bản (Flyway/Liquibase) và Hibernate chỉ validate.

Tổng kết

Sau chương 6, bạn đã nắm:

  • JPA là đặc tả, Hibernate là cài đặt, Spring Data JPA tự sinh repository; ORM không thay thế việc hiểu SQL.
  • Cấu hình PostgreSQL + HikariCP; pool nhỏ, transaction ngắn; open-in-view: false.
  • Entity: constructor rỗng, không final, EnumType.STRING, BigDecimal cho tiền, Instant cho thời điểm; record chỉ cho DTO.
  • **JpaRepository + derived query cho truy vấn đơn giản; @Query** với tham số có tên cho truy vấn phức tạp.
  • Projection lấy đúng cột cần; **Pageable** (Page/Slice) cho danh sách; chặn max-page-size.
  • Schema do migration quản lý, ddl-auto chỉ validate/none ngoài môi trường học.
